## Aktualizacja do v0.7.0 z poprzednich wersji

W skrócie: plik `glance.yml` został przeniesiony z katalogu głównego projektu do katalogu `config/`, a teraz należy zamontować ten katalog jako `/app/config` w kontenerze.

### Przed

Wersje przed v0.7.0 używały pliku `docker-compose.yml`, który wyglądał następująco:

```yaml
services:
  glance:
    image: glanceapp/glance
    volumes:
      - ./glance.yml:/app/glance.yml
    ports:
      - 8080:8080
```

I oczekiwały następującej struktury katalogów:

```plaintext
glance/
    docker-compose.yml
    glance.yml
```

### Po

Wraz z wydaniem v0.7.0 zalecany plik `docker-compose.yml` wygląda następująco:

```yaml
services:
  glance:
    container_name: glance
    image: glanceapp/glance
    volumes:
      - ./config:/app/config
    ports:
      - 8080:8080
```

I oczekuje następującej struktury katalogów:

```plaintext
glance/
    docker-compose.yml
    config/
        glance.yml
```

## Dlaczego ta zmiana była konieczna

1. Montowanie pliku zamiast katalogu nie jest powszechną praktyką i prowadzi do problemów, takich jak tworzenie katalogu, gdy plik nie istnieje, co zmyliło wiele osób i spowodowało niepotrzebne zamieszanie.
2. W v0.7.0 dodano automatyczne przeładowywanie po zmianie pliku konfiguracyjnego, które — jak pokazały testy — nie działało przy montowaniu pojedynczego pliku.
3. W v0.7.0 dodano możliwość dołączania plików konfiguracyjnych, więc i tak trzeba by było wprowadzić tę zmianę, aby skorzystać z tej funkcji.

Biorąc to wszystko pod uwagę, uznaliśmy, że to odpowiedni moment na wprowadzenie zmiany.
